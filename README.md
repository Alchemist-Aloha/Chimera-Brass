# ChimeraBrass

A browser laboratory for a human airway coupled to a trumpet. Sound is generated by a pressure-driven lip valve and acoustic waveguides, **not oscillators keyed to notes, samples, or a voice model filtered to resemble brass**.

This is a physically based educational prototype, **not a calibrated or validated trumpet digital twin**.

**Built on open-source work:** [Chimera Vocal Synth](https://github.com/jamesondh/chimera-vocal-synth) by Jameson Hodge supplies the adapted head graphic, airway anatomy and muscle-motion equation; [Pink Trombone](https://dood.al/pinktrombone/) by Neil Thapen supplied the earlier scattering/topology adaptation. MIDI parsing uses [@tonejs/midi](https://github.com/Tonejs/Midi). See [References & licensing](#references--licensing) for all code, image, font and score credits. ChimeraBrass is an independent project, not an official Chimera or Yamaha product.

## Website and deployment

GitHub Pages: https://alchemist-aloha.github.io/Chimera-Brass/

The repository remains private; the built website is public. `.github/workflows/pages.yml` installs locked dependencies, runs the numerical tests, builds Vite and deploys **only `dist/`** on pushes to `main` or a manual workflow dispatch. It sets the repository base path explicitly, so fonts, scores, licenses and the AudioWorklet load beneath `/Chimera-Brass/`. GitHub Pages must use **GitHub Actions** as its publishing source. No server, secrets or microphone access are needed by the site.

## Run

Node.js 20.19+ or 22.12+ and a current browser with AudioWorklet:

```sh
npm install
npm run dev
```

Open the URL printed by Vite, then **Start airflow**. Start with a low listening volume. Audio requires a user gesture and localhost or HTTPS.

- Change breath pressure, lip resonance, aperture and tongue arch. Drag a slider, or enter its value directly and press **Enter** (blur also applies). **Arrow keys** make small steps; **Escape** cancels an edit. Tongue arch uses percent and tract length uses centimetres; invalid values are rejected with an inline message.
- The dark workbench keeps the starting preset, **Play setup**, measured concert pitch and **Reset** in a sticky toolbar. Sound controls sit beside the instrument on desktop and stack on smaller screens; the melody keyboard and scores span the workbench below. Each curved-arrow button restores only that parameter; **Reset** restores the whole setup and stops sound. **Tune parameters** and **Play a melody** jump to those sections while playback stays accessible.
- Click valves, or hold **1 / 2 / 3**. **Space** starts/stops airflow outside editable controls.
- Choose **Tu** (front tongue) or **Ku** (rear tongue). **T / K** start airflow or re-tongue the live note; **Tongue note** uses the selected style. These are brass attacks, not spoken syllables or samples.
- **Main tuning slide** changes real tube length: pull **+** to lower pitch, push **−** to raise it. Travel is −20 to +40 mm relative to nominal, with 0.5 mm UI steps. Tune a sustained note using the measured concert note and signed **cents** relative to A4 = 440 Hz. The slide shifts resonances, not audio playback rate; large changes can require lip retuning.
- Player anatomy & physics exposes tract length, lip damping, effective lip mass and air temperature.
- Wave / Spectrum displays actual output; Bore / Pressure shows the instrument area profile or instantaneous pressure.
- The output-pitch display is measured, in **concert pitch**, not written trumpet pitch.
- Manual valve changes do not automatically retune lips. Use the 31 written-note buttons for automatic physical embouchures; a fixed manual embouchure can jump registers or lose the note.
- **Show airflow route** reveals the selected tubing. Expand the Yamaha photo reference to compare the actual instrument with the schematic.
- Audio stops when the page is hidden or loses focus. Opening model notes also stops airflow.

Fonts and audio computation are local; no microphone, sample downloads, runtime CDN or backend is required.

## MIDI and playable notes

The chromatic keyboard covers the practical written **F♯3–C6** range (31 semitones), sounding **E3–B♭5**. It does not claim every pedal, alternate fingering or extended high note. Fingering, pressure, lip resonance, aperture, damping and effective mass select each physical note. These presets are fitted against sustained 48 kHz output at 20°C with the standard 17 cm tract (the browser requests that same simulation rate); there is no audio resampling, frequency injection or pitch correction. Attack time and intonation are imperfect, especially on low notes and large register changes. Auditions hold for 3.5 seconds so onset and sustained pitch can both be inspected. Fixed valve-slide combinations can sound sharp; this model does not automatically pull the first/third tuning slides.

**Play score** performs one of three bundled Standard MIDI files:

- **Ode to Joy:** the eight-bar soprano theme from [Mutopia's public-domain score/MIDI](https://www.mutopiaproject.org/cgibin/piece-info.cgi?id=528), including its dotted-quarter/eighth-note cadences. Concert **G4–D5**, five semitones below the previous demo, at **80 BPM**. A full octave down still exposes wrong harmonic starts in the model, so this uses the lower source register rather than silently forcing the output pitch.
- **William Tell:** Rossini's overture finale **opening gallop theme**, checked against [online ABC notation](https://abcnotation.com/tunePage?a=trillian.mit.edu/~jc/music/abc/Contra/march/William_Tell_Overture-C--/0000). The two eighth-note pickups, gallop rhythm and tied high note are retained. This is a **39-note melody excerpt**, not the full overture: transposed to **D major, A4–A5 concert**, at a slow **71 BPM** practice tempo, not orchestral Presto.
- **Long-tone study:** the slow, two-minute exercise covering all 31 notes.

Source links and adaptation details appear beside the score. Original downloaded Ode MIDI/LilyPond files are retained in `third_party/scores/`; [source credits and exact changes](public/licenses/score-sources.txt) ship with the app. No restricted 8notes edition or unverified orchestral MIDI is redistributed.

The scrolling score shows written notes and highlights playback. You can download any demo `.mid`, or **Open MIDI** and select a non-percussion melody track. Parsing uses `@tonejs/midi`, including tempo maps and running status. MIDI note numbers are concert pitch, so a written C4 sounds B♭3. This is one trumpet, not a polyphonic synthesizer: chords, overlapping notes and out-of-range tracks are rejected, never silently dropped or octave-shifted. Import is local and capped at 1 MB, 128 tracks, 10,000 total notes; the selected melody is capped at 4,096 notes and 10 minutes. Sustain pedal and pitch bend are not interpreted.

Events are scheduled on the **AudioWorklet sample clock**, not browser timers. A performance starts at rest; its acoustic state continues between notes. The selected Tu/Ku tongue contact articulates each note while the pistons move. Two middle-register presets use an 80 ms physical lip-tension gesture before settling, to escape the wrong harmonic slot. MIDI velocity controls monitor expression rather than pressure, so it does not invalidate the physical tuning. Tuning and tongue style stay live through note changes and the 80 ms settling gestures; a style change applies at the next attack. Other manual controls, explicit T/K re-tonguing, stop, focus loss and model notes cancel pending events.

Regenerate bundled MIDI assets with `node scripts/make-scores.js`.

## Model

The head graphic, tongue contours and semipolar airway areas now reuse **[Chimera Vocal Synth](https://github.com/jamesondh/chimera-vocal-synth)**, MIT © 2026 Jameson Hodge. Upstream Rust anatomy exports 21 adult tongue postures; its TypeScript head/profile supplies the midsagittal SVG artwork. The same cross-sections drive both the drawing and the acoustic tract, replacing the earlier Pink Trombone diameter function and hand-drawn head. Chimera's critically damped muscle equation also controls tongue arch and lip aperture. Pinned source, license, exact adaptation and optional regeneration instructions are in [third_party/chimera/](third_party/chimera/).

The existing pressure-wave solver retains its Kelly–Lochbaum topology adapted from Neil Thapen's MIT [Pink Trombone](https://github.com/evykassirer/pink-trombone); original notices remain in [third_party/pink-trombone/](third_party/pink-trombone/). We deliberately do not import Chimera's prescribed-pitch glottal source, whole Rust/WASM voice engine or animal LipReed. This is a generic **2-D anatomical model**, not a patient scan or 3-D mesh, and the acoustic solver remains a 1-D waveguide, not Chimera's FDTD network.

### Head → lips ⇄ horn

- Chimera's semipolar mapping `A = α · d^β` supplies 44 arc-length cross-sections per exported posture. Areas are interpolated between postures, then resampled as circular-equivalent SI radii to a physical 13–21 cm tract. Tongue arch changes the actual cavity walls; the fixed oral opening is behind the separately vibrating lip valve.
- Muscle targets obey `x'' = ω²(target − x) − 2ωx'`, with tongue at 12 Hz and lip aperture at 11 Hz. Exact integration at 1 kHz avoids target jumps while preserving acoustic memory. Lip resonance uses a separate 10.4 ms first-order tension response: applying the slower speech-aperture muscle to tension caused wrong harmonic slots during transitions. These are simplified articulatory gestures, not tissue-calibrated mechanics. Area updates are quasi-static and omit moving-wall volume flow.
- An open-glottis pressure reflection of −0.85 approximates coupling to the respiratory reservoir. The velum is sealed; there is no nasal branch or voiced glottal source.
- Lung driving pressure is 0–15 kPa. It is a sustained reservoir, not a finite-volume breathing/lung fatigue simulation.
- Lips are one outward-striking mass–spring–damper degree of freedom:

  `x'' + (ω/Q)x' + ω²x = (p_mouth − p_cup) / μ`

  `h = max(0, h_rest + x)`

  `U = width · h · sign(Δp) · sqrt(2 |Δp| / ρ)`

  Constants: air density 1.204 kg/m³, aperture width 12 mm, default effective areal lip mass μ = 4 kg/m² (equivalent to 80 mg over 20 mm²), adjustable from 1–40 kg/m². Hard lip contact has restitution 0.05. The oscillator uses an implicit-midpoint integrator.

- Flow is solved analytically **against both impedances**, rather than feeding pressure into an unrelated oscillator. For incident pressure waves `a` from the tract and `b` from the trumpet:

  `p_mouth = P_lung + 2a − Z_tract U`

  `p_cup = 2b + Z_bore U`

  The positive quadratic Bernoulli root determines U, including reverse flow. Incoming reflections therefore change the force on the lips.

### Tu / Ku articulation

Airflow remains pressure-driven. **Tu** closes the supply-flow gate for 18 ms at the front of the mouth; this contact is lumped at the embouchure rather than modelling a separate small cavity behind the teeth. **Ku** closes it for 22 ms and also inserts a rear-tract acoustic constriction at 58% of the glottis-to-mouth path, near the tongue dorsum. Both release over 3 ms. The rear junction blends normal area scattering with sealed-end reflection; it is passive throughout opening. Neither gesture clears the lip oscillator or acoustic waves, adds a prescribed-pitch source, or plays a spoken consonant. The head's contact marker indicates the approximate front/rear location.

This is a simplified tongue-release model, not articulatory speech synthesis or a calibrated tongue/contact simulation. The rear closure changes nonlinear startup and can select a slightly different intonation: Ku's isolated-note regression allows 50 cents versus Tu's 25 cents. Slow low-note attacks and register-slot errors are still possible; re-tonguing is not a guarantee of immediate accurate pitch.

### Trumpet

A nominal B♭ trumpet with 1.48 m open acoustic path, visually referenced to a Yamaha YTR-8335LA photograph. Its published 11.65 mm bore and 127 mm bell diameter are used; the photograph cannot reveal the internal profile. Cup, leadpipe, flare shape and lengths remain **generic estimates, not a reverse-engineered Yamaha acoustic model**:

| Part | Geometry |
| --- | --- |
| Cup | 20 mm, taper from 16.5 mm entry diameter to throat |
| Throat | 3.7 mm diameter, 6 mm length |
| Backbore | 64 mm, opening to 9 mm diameter |
| Leadpipe | 230 mm, opening to 11.65 mm diameter |
| Cylindrical bore | 840 mm before valve and main-slide adjustments |
| Bell | 320 mm Bessel flare (exponent 1.5) to 127 mm diameter |
| Valve 1 / 2 / 3 | Independent added lengths for 2 / 1 / 3 semitones: approximately 18.1 / 8.8 / 28.0 cm |

The **main tuning slide** adds twice its signed pull distance to the open path: `L = 1.48 m + 0.002 × tuning_mm + valve_lengths`. The two legs of the U-slide move together in the drawing and the solver; piston-slide additions are unchanged. It adjusts the physical resonance, not the target note or output playback rate. The 48 kHz propagation grid rounds length to roughly 3.6 mm tube sections, so it is not continuously precise cent-level tuning. Its value is retained across MIDI performances and Reset returns it to zero.

Pressure-wave scattering conserves energy at each area junction. **Pink Trombone's original flow-wave scattering signs are converted to pressure-wave signs**; its speech-source and radiation boundary are not reused.

The propagation grid has `dx = c / (2 · audioSampleRate)`, with `c = 331.3 + 0.606 · temperature°C` m/s. The base tube and each added slide are rounded to the nearest section. Mouthpiece and flare geometry provide distributed impedance reflections; frequency-independent attenuation and a passive one-pole approximate wall losses.

The bell uses the Bessel profile `r(t) = r_entry / (1 − t · taper)^1.5`, where `taper = 1 − (r_entry/r_exit)^(1/1.5)` and `t` runs from 0 to 1. The cutaway uses this same radius function, with schematic axis scaling. Its continuous teal route runs mouthpiece → leadpipe → main tuning slide → valves 3, 2, 1 → bell return → bell; pressing a valve reroutes it through that valve's slide. The first slide points left, the long third slide right, and the small second slide projects out of plane, matching the reference rather than three dangling loops.

Four permanent waveguides and three separate slides model the piston routing. Released pistons bypass their slides; depressed pistons insert them. Unused slides remain sealed and retain their decaying pressure. A piston takes 18 ms to travel; old ports close before the new ports open at mid-stroke. A reciprocal passive constriction `S = [[r, 1−r], [1−r, r]]`, `r = sin²(π·position)`, approximates the port closure. **Valves do not rebuild or clear the air column, head or lips.** Combinations add real independent lengths rather than an artificially perfect semitone multiplier; the resulting combination intonation error is compensated only as far as the automatic embouchure can manage.

Bell-aperture reflection uses the causal, unflanged Padé fit of Silva et al. (2009), Eq. 16 / Table 1:

`R(s) = −(1 + 0.167 q) / (1 + 1.393 q + 0.457 q²)`, `q = s · r_exit / c`.

A bilinear transform makes this a stable two-pole digital filter. It approaches pressure release at DC, adds about `0.613 r_exit` of low-frequency end correction, and reduces reflection at higher frequencies without creating energy. This replaces the previous ad-hoc one-pole termination. It is still an **unflanged straight-duct approximation at a flared bell aperture**, not a measured trumpet radiation impedance.

Two-times oversampling, fourth-order Butterworth anti-alias filtering, output DC removal, a bounded soft limiter, and a separate monitor gain protect playback. Physical telemetry is taken **before** the output gain/limiter; monitor volume is not calibrated SPL. Nonfinite/excessive solver states latch silence.

### Honest limitations

- This is 1-D plane-wave acoustics, not CFD, FEM or 3-D head acoustics.
- Anatomy, tissue properties and mouthpiece/bell profile are generic assumptions, not measurements of a particular person or commercial instrument. The lower 2.4 cm larynx is a uniform extension of the first pharyngeal area, not Chimera's separate epilarynx profile.
- There is no two-mass lip model, moving-lip flow, nasal leakage, detailed tongue contact, glottal articulation, turbulence, shock-wave brassing or wall vibration.
- Wall losses are approximate, not fitted viscothermal losses. The published radiation fit is for an unflanged duct, not calibrated to this particular bell. No measured input-impedance or listening validation has been performed.
- Nominal B♭ dimensions **do not guarantee concert tuning**. The free-playing initial setup is not a prescribed B♭. The automatic keyboard uses calibrated physical controls, not perfect equal-tempered output; the UI always measures actual sound. Fast passages and some register changes can miss the intended slot.
- Piston constriction and route switching are passive approximations, not 3-D port geometry, mechanical noise or continuously measured valve flow.
- Main tuning-slide, temperature and tract-length changes fade out over 12 ms, rebuild the acoustic state, then fade back in. This is not a continuous moving-wall simulation of slide motion. Piston changes preserve the state.
- The anatomical/trumpet illustration is not to scale. Chimera head/tongue outlines and airway areas share their export; bell radii share the solver's profile. Airway-section colour/opacity visualizes pressure, not visible tissue movement. The drawn nasal cavity is sealed and not an acoustic branch. The straight bore plot uses actual radii and pressure samples.
- Numerical regression tests are not proof of acoustic realism.

## Checks

```sh
npm test                 # physics, pistons, MIDI, score timing and pitch
npm run build            # static application in dist/
npm run preview
npx playwright install chromium
npm run test:browser     # real AudioWorklet, controls, keyboard, notes, mobile
npm run render           # deterministic offline render: out/trumpet.wav
node scripts/measure-attacks.js  # all 31 rendered onset measurements (JSON)
```

For an already-installed Chromium, set `CHROMIUM_PATH=/path/to/chrome` when running browser tests. Tests launch their own server on port 5174. Set `BROWSER_PRODUCTION=1` after building to test the production bundle instead of the development server.

Onset measurements compare the previous Pink Trombone-area head/presets with the Chimera head and refitted physical controls at 48 kHz. A note must exceed 0.01 RMS and stay within 50 cents for three analysis windows. Times include the 85 ms pitch-analysis window, so they are **not raw lip latency**:

| Concert note | Before | Now |
| --- | ---: | ---: |
| B3 | 2.79 s | 2.41 s |
| C4 | 2.47 s | 1.05 s |
| D4 | 2.89 s | 1.01 s |
| E4 | 1.49 s | 0.55 s |
| F4 | 1.89 s | 0.39 s |

Across the 31 isolated notes, median measured onset improved from 0.305 s to 0.225 s. This is better, but **not realistic attack behavior for every note**: B3 still takes about 2.4 seconds and arbitrary fast low-register MIDI remains unreliable. Selected onset deadlines are regression-tested alongside settled pitch.

The same DSP module runs in Node and the AudioWorklet. Unit tests check the Bernoulli root, junction energy, physical travel time, valve lengths, vocal-tract changes, zero-pressure silence, sustained oscillation, release decay, sample-rate consistency, numerical edge cases, parameter validation and fault muting. Radiation tests check the published transfer function, passivity, low-frequency end correction and shared bell geometry. Piston tests check all eight routes, wave travel times, passive mid-stroke behavior and preserved acoustic memory. Every audition is rendered for 3 seconds with both attacks: Tu is checked within 25 cents, Ku within 50 cents. All three entire MIDI demos are checked with each articulation through one continuous model: the lower Ode to Joy and William Tell excerpts within 25 cents at their practice tempos; the chromatic long-tone study within 50 cents (combination intonation is worse than isolated notes). These are measured output tests, not just tests of requested note numbers. MIDI tests cover real bundled files, tempo changes, running status, validation, precise event frames and cancellation. Browser tests verify that the **actual worklet** produces a measurable pitch and returns to silence, and that all eight valve combinations keep one continuous mouth-to-bell diagram route. They also exercise score playback, a measured transposed audition note, MIDI import/errors and mobile reference viewing. Live tongue changes must preserve manual breath and animate the measured head geometry rather than silently sending a note-off. Articulation tests check passive contact, distinct attacks, sample-rate timing, zero-pressure silence and preserved acoustic memory. Tuning tests check doubled U-slide length, unchanged valve additions, measured pitch lowering and safe live rebuilding. Browser tests also exercise T/K, live MIDI tuning/style persistence, the shared slide drawing and signed-cents readout.

## Files

- `src/dsp/tract.js`, `src/dsp/chimera-tract.json`: Chimera area interpolation and SI radii.
- `src/dsp/articulator.js`: critically damped muscle targets.
- `src/ui/head.js`, `src/ui/chimera-head.json`: reused head/profile, tongue and pressure-section drawing.

- `src/dsp/bore.js`: permanent tube sections, slides and moving piston scattering.
- `src/dsp/trumpet.js`: lip dynamics, tongue release and nonlinear bidirectional coupling.
